# SphereBrain 研究チェックポイント — 経験予測・パズル観察・経路読み出し

**日付:** 2026-09-18  
**位置づけ:** 公開研究記録。Coreへの正式昇格ではなく、汎用知能の主張でもない。

この区切りでは、次の問いを人間の目で追える形にした。

> 一つの個体が実経験から学び、その経験を別の状態へ使い、さらにSphereBrain自身の持続的な経路が予測や行動へ寄与できるのか。

いくつかの動作は実現できた。一方で、改善の一部は明示的に設計した予測記憶や仮説管理規則によるものであり、**SphereBrain固有のnative route dynamicsだからこそ有利だった**という点はまだ確認できていない。

そのため、ここでは機能追加をいったん止める。次の研究は「もう一つ機能を足せるから」ではなく、続ける価値を判断できる問いと停止条件が定まったときに再開する。

## 1. 「2枚のカギ」

人間が触れる形で、次の流れを観察した。

- 解けていない課題Aを保留する
- 近い別課題Bで経験する
- Bで得た経験によりAへ戻る判断が変わる
- 以前の条件Pで使えた技法も保持する

慎重なProgress Gateを入れた3開発世界では、Aへ再開した後の失敗が **6回 → 0回** に減った。

一方、初期取得・B・A・旧条件Pの確認を含む総実試行は **53回 → 91回** に増え、Aの成功も遅くなった。

したがって残せるのは、

> 「候補が変わった」ことと、「同じ候補を再び試す正の根拠が増えた」ことを分けられた

という結果であり、「慎重版のほうが優秀」「より自律的になった」という結論ではない。

## 2. Flip Learning Loop

Flipは盤面と操作を人間が直接見られるため、経験学習の観察環境として使った。

新しい個体には過去ログや反転ルールを渡さず、実際の「操作前状態 + 操作 + 操作後状態」だけを経験として与えた。

保存されたv2 seed 42個体では、

- **19回の実操作**で目標へ到達
- その時点で **131 / 162条件**を観測済み
- 最後の一手は実行前に全マス0になると予測
- 最後の **9 / 9マス**の予測が実結果と一致

した。

ただし、この直接予測を生んだのは**設計した条件別記憶**である。SphereBrain本体のsubstrateは実状態・遷移を記録していたが、この成功をnative route reasoningの成果とは扱わない。

ここで確認できたのは、

> 実経験が増える → 予測できる範囲が変わる → 選ぶ行動が変わる

という学習ループそのもの。

## 3. Route Readout v1

同じ19実経験を使い、native Coreの遷移から結果を読み出せるか調べた。

学習後には、

- 経験済み19組を **19 / 19** 再現
- readout切断で予測不能
- transitionを0にしても予測不能
- 結び先を入れ替えると再現が大きく崩れる

ことを確認した。

一方、各結果を知る前の19判断では、慎重な採用条件のもとで **0 / 171マス**しか予測として採用できず、行動選択も変わらなかった。

ここで得たのは既知対応の経路読み出しであり、未経験状態への転用ではない。

## 4. Route Readout v2

経験した複数経路の一致・不一致を比較し、結果を区別するのに必要そうな入力部分を学ぶ拡張を加えた。

非空間的な生成環境では未経験の全体状態への転用が起きた。

しかし、

- 正の経路重みをすべて同じにしても結果が変わらない
- 普通の経験記録に**同じ学習規則**を使っても結果が一致

した。

したがって、転用を生んだ中心は新しく設計した入力部分の選択規則であり、native Core固有の数値動態の優位性は示せなかった。

また、まだ決定的な入力組合せを経験していない箇所を早く「定数」と単純化しすぎたため、**12件の誤予測**が出た。

## 5. Route Readout v3

v3では、

> 共通して使える部分は使う。  
> まだ区別できていない違いは、一つへ決めない。

という方針へ変えた。

経験と矛盾しない0/1/2入力候補をすべて残し、未経験条件は未解決のまま保持した。

結果として、

- v2の誤り12件はv3では**すべて保留**
- 10個の新しい診断環境すべてで、同じ24回の追加経験なら、曖昧さを使った経験選択が再現可能なランダム順序より広い最終予測範囲を得た
- 同時点で曖昧さスコアへの接続だけを切ると、**240判断中233判断**で選ぶ実験が変わった

ことを確認した。

ただし、普通の経験記録へ同じ候補保持・選択規則を使う対照と、報告した予測・選択は一致した。

よって、

> 曖昧さを残し、区別に必要な経験を選ぶ方法には限定的な有効性がある

とは言えるが、

> SphereBrainの経路の太さ・競合・native dynamicsだからこそ有効だった

とはまだ言えない。

## 6. この区切りで残せること

1. 実経験と想像上の予測を分けたまま、経験がその後の予測と選択を変える仕組みを実装できた。
2. パズルという人間が観察できる環境で、その学習ループと限界を見られる形にできた。
3. 経験済みnative route接続から既知の対応を読み出せた。
4. 限定モデルでは、共通部分を再利用しながら未解決の違いを残す方式を構成できた。
5. 未解決の違いを区別する経験を選ぶことで、試した診断環境では無情報な順序より学習範囲を広げられた。

## 7. まだ言えないこと

- 汎用的なパズル解法
- 広い意味での自律planning
- 汎用人工知能
- 普遍的な因果法則の発見
- 同じ上位学習規則を使う普通の記憶方式に対するnative SphereBrain routeの優位性
- route weightの太さやnative competitionが今回の転用を生んだという因果主張
- 最大2入力という限定を超えた一般化

## 8. なぜここで止めるのか

このまま機能を一つずつ追加すると、研究の問いが

> 経験による内部構造に、固有で有用な働きがあるか

から、

> 次に何を追加すれば、もう一つできることが増えるか

へずれてしまう。

そこで、このチェックポイントでは機能追加を止める。

次の研究は、

- 何を確かめるために再開するのか
- 何が出れば「続ける価値がある」と判断するのか
- 何が出なければ、この系列を終えるのか

を先に決めてから始める。

**システムが未完成であることと、研究記録が未完成であることは同じではない。**

ここまでを、成功・失敗・代償・帰属できなかった部分を含めて、一つの公開チェックポイントとして残す。
