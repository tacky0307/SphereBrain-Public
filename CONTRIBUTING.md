# Contributing to SphereBrain

SphereBrain welcomes reproduction, criticism, falsification, alternative explanations, experiment proposals, documentation corrections, and carefully scoped code contributions.

## Before contributing

Read:

- [README.md](README.md)
- [PHILOSOPHY.md](PHILOSOPHY.md)
- [ARCHITECTURE.md](ARCHITECTURE.md)
- [LIMITATIONS.md](LIMITATIONS.md)
- [OPEN_RESEARCH_POLICY.md](OPEN_RESEARCH_POLICY.md)
- [REPRODUCE.md](REPRODUCE.md)

A contribution does not need to support the SphereBrain hypothesis. Well-documented negative evidence is especially valuable.

## Useful contribution types

### Reproduction

Include the exact commit, operating system, Python version, dependency versions, runner, seeds, raw output, and any deviation from the documented procedure.

### Falsification

State the claim being tested, an alternative explanation, the control or intervention, the observed result, and what conclusion the result does or does not support.

### Alternative explanation

Identify the exact measurement or experiment and explain a mechanism that could produce the same observation without the proposed interpretation.

### Experiment proposal

Prefer a small discriminating experiment over a large demonstration. Define:

- hypothesis;
- baseline and controls;
- manipulated variable;
- measurement;
- predefined success and failure conditions;
- likely confounds;
- expected raw output.

### Code or documentation

Keep historical versioned experiments immutable in spirit. Correct errors transparently or create a new follow-up version instead of silently rewriting the research record.

## Reporting results

Use this structure where practical:

```text
Hypothesis
Method
Environment
Observed result
Interpretation
Alternative explanations
Limitations
Next test
```

Do not describe a runner-level PASS as proof of intelligence, meaning, consciousness, or biological equivalence.

## Data and privacy

Do not submit:

- secrets, API keys, tokens, or credentials;
- personal or medical information;
- third-party data without redistribution rights;
- generated output whose license or provenance is unclear;
- large binary files without prior discussion.

Use synthetic or openly redistributable data where possible and document provenance.

## AI-assisted contributions

AI-assisted code or writing is permitted when allowed by the contributor's tools and context. Disclose material AI assistance. The human contributor remains responsible for verifying the submission, its license, and its claims.

## Licensing

Unless explicitly stated otherwise, contributions intentionally submitted for inclusion are provided under the repository's Apache License 2.0.

## Conduct

Engage with claims and evidence, not personal status. Criticism should be specific, reproducible where possible, and open to correction. Harassment, discrimination, threats, or deliberate misrepresentation are not acceptable.

## Security

Do not publish credentials or security-sensitive details in a public issue. Follow [SECURITY.md](SECURITY.md).
